R-01 • Thành công
Happy Path (Đơn hàng Chuẩn)

Giữ kho thành công -> Thu tiền thành công -> Đơn CONFIRMED, Saga COMPLETED.

R-02 • Hết Hàng
Out of Stock (Thiếu Hàng)

Đặt quá số lượng khả dụng -> Giữ kho thất bại -> Đơn REJECTED, bỏ qua thanh toán.

R-03 • Bồi Hoàn
Thanh Toán Lỗi (Compensation)

Thẻ từ chối -> Kích hoạt Bồi hoàn (Release kho) -> Đơn CANCELLED, kho hoàn trả.

R-05 • Phục Hồi
Timeout Recovery (Treo Cổng)

Cổng thanh toán timeout -> Tự động giải phóng kho bảo vệ tính nhất quán.

📡 Bản Đồ Kiến Trúc Vi Dịch Vụ (Bounded Contexts)
1. API Gateway (Port 3000)
Routing, JWT AuthN/AuthZ (RBAC), Reverse Proxy, OpenAPI 3.0 Documentation.
2. Catalog Bounded Context
Quản lý dữ liệu danh mục sản phẩm, đơn giá, DTO validation, CQRS queries.
3. Inventory Bounded Context
Atomic Conditional Update (available_stock >= requested), Multi-item atomic lock, Anti-overselling.
4. Ordering Bounded Context & Saga Orchestrator
Order Aggregate State Machine, Saga Orchestrator, Compensation Rollback, Outbox/Inbox Broker.
5. Payment Gateway Simulator (External Adapter)
Mô phỏng cổng thanh toán đối tác thứ 3, hỗ trợ kiểm thử thành công, thất bại, và timeout.
📬 Cơ Chế Chịu Lỗi & Outbox-Inbox Pattern

• Nguyên lý Idempotency (Chống trùng lặp): Mọi bước xử lý trong Saga và Event Bus đều kiểm tra Idempotency Key để đảm bảo một sự kiện khi được broker gửi lại nhiều lần (at-least-once delivery) không gây ra trừ trùng kho hay thanh toán kép.


• Saga Compensation: Khi bất kỳ dịch vụ nào ở phía sau gặp lỗi (ví dụ: thẻ tín dụng không đủ tiền, cổng thanh toán sập), Orchestrator sẽ kích hoạt lệnh Bồi hoàn ngược chiều để giải phóng kho hàng đã giữ trước đó.


• Zero Database Sharing: Từng Bounded Context hoàn toàn làm chủ dữ liệu của mình, tuyệt đối không có foreign key vật lý hay query trực tiếp sang schema của service khác.
