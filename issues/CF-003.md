# CF-003 — Requirements, use cases và acceptance scenarios

**Milestone:** M1  
**Effort:** 3 giờ · **Mode:** Guided · **Loại:** `lab`  
**Phụ thuộc:** CF-002  
**Trạng thái kiểm chứng:** `verified` (bằng chứng tại `evidence/CF-003/README.md`)

## Vấn đề và mục tiêu
Mô tả tạo đơn thành công, hết hàng, thanh toán lỗi kèm Given/When/Then. Đầu ra này đóng góp cho CommerceFlow và phải gắn với scenario trong `docs/requirements.md`.

## Kiến thức và thuật ngữ
Trước khi thực hành, đọc [bảng thuật ngữ](../docs/glossary.md) và [kiến trúc](../docs/architecture.md). Ở lần đầu gặp acronym, tra tên tiếng Anh đầy đủ, diễn giải tiếng Việt, ví dụ và những hiểu lầm phổ biến. Trong Issue này hãy giải thích: **Requirements, use cases và acceptance scenarios**. Tài liệu chuẩn tham khảo nằm trong [docs/sources.md](../docs/sources.md); xác nhận version trước khi chạy lệnh yêu cầu cài package.

## Prerequisites & môi trường
- Working directory: root repository; Node.js mục tiêu 24 LTS (micro-lab kiểm tra trên Node cài trong môi trường hiện tại); dùng Bash/macOS/Linux, Windows dùng WSL2 hoặc PowerShell với câu lệnh Node tương đương.
- Phải hoàn thành: CF-002. Chỉ dùng dữ liệu mẫu; không dùng credentials thật.
- Với các bài cloud, `node labs/CF-003/demo.mjs` **không tạo tài nguyên**. Terraform apply / gcloud deploy chỉ được thực hiện sau khi duyệt riêng.

## Step-by-step lab
1. **Đọc tình huống:** Mô tả tạo đơn thành công, hết hàng, thanh toán lỗi kèm Given/When/Then. Ghi đầu vào, đầu ra, business invariant và negative case vào `evidence/CF-003/README.md`.
2. **Chạy ví dụ thu nhỏ:** tại repository root chạy `node labs/CF-003/demo.mjs` và quan sát `MICRO_LAB_OK CF-003`. Nếu lỗi `ERR_MODULE_NOT_FOUND`, kiểm tra working directory và Node version.
3. **Đọc và chỉnh ví dụ:** mở `labs/CF-003/demo.mjs`; giải thích từng assertion. Đổi một input để assertion thất bại rồi phục hồi code, nhằm quan sát false-negative/positive và exit code.
4. **Tạo artifact sản phẩm:** `docs/requirements.md`. Mô tả tạo đơn thành công, hết hàng, thanh toán lỗi kèm Given/When/Then. Không xem micro-lab này là code production; kết nối với các artifact dependencies và bổ sung test tương ứng.
5. **Thực hiện negative test:** kiểm tra ít nhất một tình huống biên; ghi lệnh thật, expected/observed output và trạng thái trong `evidence/CF-003/README.md`. Nếu chưa có đầy đủ code từ Issues trước, đánh dấu `blocked`, không ghi `passed`.
6. **Review:** đối chiếu danh sách Acceptance Criteria, nêu rủi ro và giải thích quyết định thiết kế cho người review.

## Annotated code/script — ví dụ có thể chạy

```javascript
// Ví dụ độc lập: dùng assert để tạo tín hiệu pass/fail có thể lặp lại.

const scenario = {given: 'stock=1', when: 'reserve(2)', then: 'rejected'};
assert.equal(scenario.then, 'rejected');
console.log('MICRO_LAB_OK CF-003');
```
