# CF-002 — Chuẩn bị môi trường và smoke tests an toàn

**Milestone:** M1  
**Effort:** 3 giờ · **Mode:** Guided · **Loại:** `environment`  
**Phụ thuộc:** CF-001  
**Trạng thái kiểm chứng:** `draft/unverified` (micro-lab được chạy riêng, không chứng minh Issue hoàn tất)

## Vấn đề và mục tiêu
Ghi nhận version Node, Git, Docker, pnpm và chạy starter tests. Đầu ra này đóng góp cho CommerceFlow và phải gắn với scenario trong `docs/requirements.md`.

Trước khi thực hành, đọc [bảng thuật ngữ](../docs/glossary.md) và [kiến trúc](../docs/architecture.md). Tài liệu chuẩn tham khảo nằm trong [docs/sources.md](../docs/sources.md); xác nhận version trước khi chạy lệnh yêu cầu cài package.

## Prerequisites & môi trường
- Working directory: root repository; Node.js mục tiêu 24 LTS (micro-lab kiểm tra trên Node cài trong môi trường hiện tại); dùng Bash/macOS/Linux, Windows dùng WSL2 hoặc PowerShell với câu lệnh Node tương đương.
- Phải hoàn thành: CF-001. Chỉ dùng dữ liệu mẫu; không dùng credentials thật.
- Với các bài cloud, `node labs/CF-002/demo.mjs` **không tạo tài nguyên**. Terraform apply / gcloud deploy chỉ được thực hiện sau khi duyệt riêng.

## Step-by-step lab
1. **Đọc tình huống:** Ghi nhận version Node, Git, Docker, pnpm và chạy starter tests. Ghi đầu vào, đầu ra, business invariant và negative case vào `evidence/CF-002/README.md`.
2. **Chạy ví dụ thu nhỏ:** tại repository root chạy `node labs/CF-002/demo.mjs` và quan sát `MICRO_LAB_OK CF-002`. Nếu lỗi `ERR_MODULE_NOT_FOUND`, kiểm tra working directory và Node version.
3. **Đọc và chỉnh ví dụ:** mở `labs/CF-002/demo.mjs`; giải thích từng assertion. Đổi một input để assertion thất bại rồi phục hồi code, nhằm quan sát false-negative/positive và exit code.
4. **Tạo artifact sản phẩm:** `docs/environment.md`. Ghi nhận version Node, Git, Docker, pnpm và chạy starter tests. Không xem micro-lab này là code production; kết nối với các artifact dependencies và bổ sung test tương ứng.
5. **Thực hiện negative test:** kiểm tra ít nhất một tình huống biên; ghi lệnh thật, expected/observed output và trạng thái trong `evidence/CF-002/README.md`. Nếu chưa có đầy đủ code từ Issues trước, đánh dấu `blocked`, không ghi `passed`.
6. **Review:** đối chiếu danh sách Acceptance Criteria, nêu rủi ro và giải thích quyết định thiết kế cho người review.

## Annotated code/script — ví dụ có thể chạy
Đường dẫn: `labs/CF-002/demo.mjs`.

```javascript
// Ví dụ độc lập: dùng assert để tạo tín hiệu pass/fail có thể lặp lại.
import assert from 'node:assert/strict';
const versions = {node: process.versions.node, platform: process.platform};
assert.ok(Number(versions.node.split('.')[0]) >= 20);
console.log('MICRO_LAB_OK CF-002');
```

**Lệnh:** `node labs/CF-002/demo.mjs`  
**Kỳ vọng:** in `MICRO_LAB_OK CF-002`, exit code 0. Đây chỉ là smoke test của khái niệm, không phải acceptance test end-to-end.
