# CF-039 — Failure drills, security, cost review và recovery

**Milestone:** M8  
**Effort:** 4 giờ · **Mode:** Guided · **Loại:** `review`

Ghi runbook failure injection, restore/rollback và billing audit. Đầu ra này đóng góp cho CommerceFlow và phải gắn với scenario trong `docs/requirements.md`.

## Prerequisites & môi trường
- Working directory: root repository; Node.js mục tiêu 24 LTS (micro-lab kiểm tra trên Node cài trong môi trường hiện tại); dùng Bash/macOS/Linux, Windows dùng WSL2 hoặc PowerShell với câu lệnh Node tương đương.
- Phải hoàn thành: CF-038, CF-037. Chỉ dùng dữ liệu mẫu; không dùng credentials thật.
- Với các bài cloud, `node labs/CF-039/demo.mjs` **không tạo tài nguyên**. Terraform apply / gcloud deploy chỉ được thực hiện sau khi duyệt riêng.

## Step-by-step lab
1. **Đọc tình huống:** Ghi runbook failure injection, restore/rollback và billing audit. Ghi đầu vào, đầu ra, business invariant và negative case vào `evidence/CF-039/README.md`.
2. **Chạy ví dụ thu nhỏ:** tại repository root chạy `node labs/CF-039/demo.mjs` và quan sát `MICRO_LAB_OK CF-039`. Nếu lỗi `ERR_MODULE_NOT_FOUND`, kiểm tra working directory và Node version.
3. **Đọc và chỉnh ví dụ:** mở `labs/CF-039/demo.mjs`; giải thích từng assertion. Đổi một input để assertion thất bại rồi phục hồi code, nhằm quan sát false-negative/positive và exit code.
4. **Tạo artifact sản phẩm:** `docs/testing/failure-drills.md`. Ghi runbook failure injection, restore/rollback và billing audit. Không xem micro-lab này là code production; kết nối với các artifact dependencies và bổ sung test tương ứng.
5. **Thực hiện negative test:** kiểm tra ít nhất một tình huống biên; ghi lệnh thật, expected/observed output và trạng thái trong `evidence/CF-039/README.md`. Nếu chưa có đầy đủ code từ Issues trước, đánh dấu `blocked`, không ghi `passed`.
6. **Review:** đối chiếu danh sách Acceptance Criteria, nêu rủi ro và giải thích quyết định thiết kế cho người review.
